# Avatar renderer decision

Status: Phase 2 runtime proof landed with owned procedural GLBs and a
`model_viewer_plus` 1.10.0 WebView bridge. Flutter remains pinned to 3.44.8;
no SDK migration is required for the current vertical slice.

## Constraints

- The repository is pinned to Flutter 3.44.8 for the current Xcode 27 baseline.
- The repository contains two owned procedural GLBs generated by Blender 4.5.9.
- Each GLB contains one shared skin, the common garment material namespace, and
  five named animation clips. Asset hashes and the material/animation contract
  are checked by `tools/avatar/validate_assets.sh`.
- A wardrobe photograph is not treated as an exact 3D garment reconstruction.
  The first supported representation is a metadata-selected template with a
  detected color/material treatment.
- Guest wardrobe images stay local. No avatar renderer may require uploading a
  guest image.

## Candidate evidence

| Requirement | `model_viewer_plus` 1.10.0 | `flutter_scene` 0.23.0 |
| --- | --- | --- |
| iOS / Android support | Package advertises both; WebView runtime | Package advertises both; Flutter GPU / Impeller runtime |
| Local GLB | Supported by `src` | Supported by runtime import and build-time conversion |
| Orbit / drag | `cameraControls` | Scene camera/input layer |
| Skeletal animation | `animationName` / `autoPlay` | Skinned meshes and blended animation |
| Material variant | `variantName` | `KHR_materials_variants` / `SceneModel.variant` |
| Independent garment node swap | Implemented through fixed bridge JavaScript and material opacity/base-color updates on one loaded GLB; interactive swap remains device-gated | Scene graph supports the required architecture |
| Flutter integration | WebView platform view; gesture and lifecycle cost | Native Flutter scene view |
| Current Flutter pin | Compatible dependency already resolved | Current docs require Flutter 3.47+ and Flutter GPU |
| MMM prototype result | Implemented with one loaded GLB, fixed JSON look payload, material groups, procedural pattern textures, animation control, and fallback; static bridge/asset checks pass | API inspected; package not added because the pin is incompatible |

The `model_viewer_plus` implementation loads the real GLB runtime path in the
iPhone simulator smoke pass. Native device performance, interactive garment
swaps, and the full Xcode 27 Device Hub matrix still require
interactive/device evidence. The GLBs are deliberately stylized procedural
approximations, not photo-to-mesh reconstruction.

## Decision

`model_viewer_plus` is the Phase 2 renderer because the existing Flutter
baseline already supports its WebView/controller seam and the prepared GLB
material groups make independent garment visibility/color changes possible
without reloading the model. `GlbAvatarRenderer` sends a JSON payload to the
fixed `window.mmmAvatar.applyLook` function through `relatedJs`, JavaScript
channels, and `WebViewController.runJavaScript`.

`flutter_scene` remains a future native-renderer candidate. It is not adopted on
this branch because its current SDK requirements do not match the repository's
Flutter 3.44.8 pin, and a migration is not justified after the working WebView
vertical slice.

## Runtime contract

```text
ClothingItem (wardrobe truth)
  -> WearableTemplateResolver
  -> WearableAsset (template, slot, color, material, fit)
  -> AvatarOutfitResolver (real Outfit.itemIds, deterministic layers)
  -> GlbAvatarRenderer when a validated base model exists
  -> existing static fallback while the renderer is unavailable
```

The resolver handles dress/top/bottom conflicts, duplicate slots, missing
wardrobe IDs, and failed wearable processing without mutating the outfit or
wardrobe. The generated semantic label lists the selected garment names.

## Phase 2 evidence

- Renderer assets: `human_female_v1.glb` 651,576 bytes and
  `human_male_v1.glb` 651,552 bytes; both contain 14,852 triangles, one skin,
  and `idle`, `blink`, `wave`, `look`, `outfit_reveal`.
- Validation: Khronos `gltf-validator` package `2.0.0-dev.3.10`; both GLBs
  report zero errors and zero warnings. Catalog hashes and required material
  groups/animations pass the repository validator.
- Runtime updates: outfit changes call `applyLook` on the existing WebView;
  normal outfit changes do not replace the `ModelViewer` key or reload the GLB.
- Patterns: stripe, plaid, graphic, and other simple patterns use local
  procedural canvas textures; guest photos are not uploaded or mapped directly.
- Fallback: pets retain the existing painter; renderer load/update failure
  returns to the existing 2D fallback.
- Device Hub / physical Android runtime: **BLOCKED — interactive device bridge
  evidence is not available in this environment.**
